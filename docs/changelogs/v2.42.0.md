# v2.42.0 (2026-09-11)

> 版本范围：v2.41.0..HEAD

## 新功能

- **feat(req): `/req:review-pr` 大 PR 改调原生 `/code-review`，删除 `file-reviewer` agent**
  - 第 1 步改为本地 git 取 diff 判规模：fetch PR 分支与 `mergeTarget` 后 `git diff --stat`；小 PR（≤10 文件且 ≤800 行）读全量 diff，大 PR 只派 `diff-digest` 取摘要，diff 原文不进主会话。第 3 步需求比对在大 PR 下用摘要的文件清单与结构性改动，不拉原文
  - 第 4 步大 PR 不再自研逐文件委派，调用原生 `/code-review`（Skill 工具，`allowed-tools` 加 `Skill`）：GitHub 传 PR 号，Gitea / other 传 ref 范围 `<mergeTarget>...<branch>`；不加 `--comment`，评论统一走第 6 步；Important / Nit / Pre-existing 映射为阻塞 / 建议 / 信息。原生不可用时退回内联审查并在报告首行注明
  - 档位按 PR 复杂度打分自动选（`--level=` 可覆盖），信号全部来自 `numstat` 与 `diff-digest` 的结构性改动清单：规模大 / 契约变更 / 敏感路径 / 缺测试 / 跨模块各 +1，QUICK 或 hotfix / 非代码为主各 −1；≤ −1 → `low`，0~1 → `medium`，≥ 2 → `high`。输出打印命中的信号便于调阈值；不自动选 `max`，`ultra` 只在报告末尾提示
  - 依据是同一 13 文件 PR 的实测对比：自研路径（haiku digest + 13 个 sonnet file-reviewer）要主会话先读全量 diff 再抄进每个 prompt，「diff 不进主会话」不成立，且有 1 条误报（reviewer 读工作区 HEAD 而非 PR ref）、10 多条跨文件疑点留给主会话；原生 27 候选去重 12、验证 8 条全确认、无误报，约 1.7× 成本、耗时相近。原生 fork 跑在会话模型上，成本随会话模型走
  - `CLAUDE.md`、`shared/_delegate.md`、`docs/design/token-optimization.md` 同步为 5 个 agent，`diff-digest` 保留（`pr` / `commit` / `review-pr` 仍用）
