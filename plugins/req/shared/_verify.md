# 公共逻辑参考 - 执行后验证

> 供 `/req:do`、`/req:fix` 在代码改完后、完成提示前执行。四条原则：**验证顺序固定、结果必报、无覆盖显式说出、失败修复有上限**。
>
> 同伴文档（同目录，按需 Read；此处不用链接，避免把整组共享文件拖进上下文）：`_delegate.md`（test-runner / impl-worker 委派规则）。

## 前置：方案里的验收行

方案的每个改动单元附一行「验收」，二选一：

- **可执行命令**：来自 `docs/prompt/testing.md`「必备输入」的测试命令、或 `docs/prompt/architecture.md` 的构建 / lint 命令，已按本单元拼好过滤参数
- **可观察行为**：一句话，写清输入与预期输出（用于没有自动化手段的单元）

验收行同时就是 `_delegate.md`「委派实施」准入第四条「有验收手段」的凭据：**没有可执行命令做验收的单元不能派 `impl-worker`**，主会话自己改。

重构 / 优化 / 升级 / 规范类改动，方案还要附一行「行为变化：无」或列出有意改变的行为；这决定后面测试失败时能不能改断言。

## 验证顺序（固定）

任一级缺少配置就跳过，并在验证结果里写「未配置」，不得静默省略。

1. **编译 / lint**：命令取自 `testing.md`「必备输入」或 `architecture.md`；主会话直接执行。失败先修再往下。
2. **相关测试回归**：按改动文件定位对应测试文件——优先 `testing.md` 里的文件位置 / 命名规则，没有规则时按同名 / 同目录的语言惯例找。派 `test-runner`，prompt 自包含（工作目录、拼好的命令、本次要跑的测试文件清单、返回格式）；测试日志不进主会话。
3. **覆盖判断**：改动文件没有任何对应测试时，按意图类型分流：
   - **小功能 / 修复**：询问用户是否补 UT；同意则按 `test_new.md` 的 `--type=ut --files=<改动文件>` 无文档模式生成，回跑一次。
   - **优化 / 重构 / 升级 / 规范**（目标是行为不变）：不强行补测试。记为「无测试覆盖」，并从方案的改动点派生**手动验证清单**：每条对应一个改动点的可观察行为，写成可勾选项。

## 失败处理

- 测试失败 → 修代码 → 重跑，**最多 2 轮**。仍失败则停下，把 `test-runner` 返回的失败清单原样交给用户，不进入完成提示。
- **红线：不得为了让测试通过而修改断言、期望值、跳过或删除用例。** 唯一例外是方案的「行为变化」行已声明该行为改变且用户已确认；此时改测试要在验证结果的「测试改动」里逐条列出原因。
- `test-runner` 回 `ERROR`（依赖缺失、命令不存在、编译失败）→ 报告原因并询问用户，不改命令、不换框架绕过。

## 验证结果段

放在完成提示中，与「修改文件」并列。缺项写「未配置」或「无」，不得省略整段。

```
验证结果：
- 编译：✓ | ✗ | 未配置
- lint：✓ | ✗ | 未配置
- 测试：<通过数>/<总数> 通过（<命令>） | 未配置
- 无测试覆盖：<文件列表> | 无
- 手动验证：
  - [ ] <改动点对应的可观察行为>
- 测试改动：<改了哪个用例、原因> | 无
```

后续 `/req:commit` 不重跑验证，直接采信这段；`/req:review-pr` 审查时可对照它检查覆盖缺口。
